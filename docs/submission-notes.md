# 대전 실시간 기온 — 오늘의 진짜 정보판 (T04)



비개인 공개 원천(Open-Meteo)에서 실제로 변하는 기온 값을 조회해, 값·단위·출처·관측 시각·조회 시각·기준 시간대를 보여 주는 정보판입니다. 데이터가 오지 않을 때도 마지막 정상값을 유지하면서 현재 상태를 정직하게 설명합니다.



## 공개 주소



- **결과물(무로그인 공개)**: https://ilb72.github.io/weather-board/

- **소스**: https://github.com/ilb72/weather-board



> 위 두 주소는 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 새 시크릿 창에서 열립니다.



## 무엇을 보여 주나



- **값 + 단위**: Open-Meteo 현재 기온 (예: `22.1 °C`)

- **출처**: Open-Meteo (대전 좌표 `36.35, 127.38`)

- **관측 시각(source_time)** 과 **조회 시각(fetched_at)** 을 분리 표시

- **기준 시간대**: `Asia/Seoul` (KST)

- **기록 날짜(record_date)**: `fetched_at`을 KST로 변환한 날짜

- **날씨(표시용)**: `weathercode`를 한국어로 매핑해 히어로·관측 정보·어제와 비교·일별 기록 표에 표시합니다. 저장 객체(`reading`)는 9개 필드를 유지하고, 날씨는 행 레벨 `weather_display`로만 보관합니다.

- **데이터 상태**: `freshness`(fresh/stale) + `error_code`(none/timeout/auth/rate_limit/offline/schema_error)

- **마지막 정상값**: 실패 시에도 유지

- **일별 기록**: `signal_id + record_date` 기준으로 같은 날은 갱신, 다음 날짜는 새 행

- **어제 대비**: 라이브 기록 2건(서로 다른 KST 날짜)이 쌓이면, 날짜순으로 정렬해 `최신값 − 이전값`의 절대값을 표시합니다. 예: 10/26 22.1°C → 10/27 23.4°C이면 `1.3 °C`.



## 비밀값 없음



- API 키가 필요 없는 공개 원천(Open-Meteo)만 사용합니다.

- 브라우저 코드·배포 파일·네트워크 요청·Git 기록에 비밀키 원문이 없습니다.

- 저장소 전체에서 `API_KEY`, `secret`, `token` 등을 검색해 0건임을 확인했습니다.



## 저장 규칙



- 정규화 형식은 `normalized-reading.schema.json`의 9개 필드를 따릅니다:

  `signal_id`, `normalized_value`, `unit`, `source_name`, `source_url`, `source_time`, `fetched_at`, `record_timezone`, `record_date`

- `record_date`는 `fetched_at`을 `Asia/Seoul`로 변환한 날짜와 일치해야 합니다.

- 같은 `signal_id + record_date`는 새 행을 만들지 않고 갱신합니다.

- 다음 `Asia/Seoul` 날짜의 성공 조회는 새 일별 행을 만듭니다.

- 실패는 정상값을 덮어쓰거나 지우지 않습니다.

- 같은 날짜 재생은 행을 늘리지 않고 갱신합니다. "다음 날 1회"를 반복 재생해도 8/25 행은 1개로 유지됩니다(같은 날짜이기 때문).

- "정상 조회(라이브)"는 오늘 날짜 행을 갱신합니다. 같은 날짜에 여러 번 조회해도 행은 1개이며, 다음 KST 날짜에 조회하면 새 행이 생깁니다.

- 날씨는 저장 객체(`reading`)에 넣지 않고 행 레벨 `weather_display`로만 보관합니다. 9개 필드 스키마(`additionalProperties: false`)를 유지하기 위함입니다.



## 장애 처리 (합성 재생)



심사용 섹션에서 아래 5종을 합성 시험값으로 재생할 수 있습니다.



| 재생 | error_code | 동작 |

|---|---|---|

| 느린 응답 | `timeout` | 마지막 정상값 유지, stale 표시 |

| 401 거절 | `auth` | 마지막 정상값 유지, stale 표시 |

| 호출 제한(429) | `rate_limit` | `retry_after_seconds` 기록, stale 표시 |

| 오프라인 | `offline` | 마지막 정상값 유지, stale 표시 |

| 형식 변경 | `schema_error` | 마지막 정상값 유지, stale 표시 |

| 복구(recover-d2) | `none` | `fresh / none`으로 복귀, 다음 합성 날짜(2026-08-25)에 값 120 행 1건 추가, delta 15 |



합성 재생은 **실제 이틀 비교에 사용되지 않습니다.** 실제 비교는 라이브 기록 2건만 사용합니다.



## 실제 이틀 기록 확보



- 1일차(2026-10-26): 페이지 접속 시 자동 조회로 `2026-10-26` 라이브 기록 1건 저장.

- 2일차(2026-10-27): 같은 주소에 다시 접속하면 자동 조회로 `2026-10-27` 라이브 기록 1건 추가.

- 두 기록은 `일별 기록` 표에 LIVE 태그로 표시되며, 상단 "어제와 비교"에 변화량이 표시됩니다.

- 합성 재생(SYNTHETIC)은 이 비교에 사용되지 않습니다.



## 확인 방법 (4줄)



1. **어디로 가나요**: https://ilb72.github.io/weather-board/ 상단 "대전 실시간 기온" 히어로와 "관측 정보" 표.

2. **3단계 이내 무엇을 하나요**: 상단 값·관측/조회 시각 확인 → "테스트" 섹션 펼침 → 장애 재생 5종 버튼 각각 클릭 후 복구 버튼 클릭.

3. **무엇이 보이면 통과인가요**: 정상 시 9개 필드가 모두 표시되고, 장애 시 마지막 정상값이 유지되며 상태 배지가 stale·오류 코드로 바뀝니다. 복구 시 fresh/none으로 돌아오고 전체 행 수가 1→2로 증가하며 어제 대비 delta=15가 표시됩니다(합성 재생 기준). 라이브 이틀 기록이 2건이면 상단 "어제와 비교"에 실제 변화가 표시됩니다.

4. **안 될 때 무엇이 보이나요**: 네트워크 차단 시 상태 배지가 stale·offline으로 바뀌고 마지막 정상값의 조회 시각이 함께 표시됩니다.



## AI와 나의 판단 (3줄)



1. **AI에게 맡긴 일**: 정보판 HTML/CSS/JS 초안, 9개 필드 정규화 검증, 실패 5종 상태 매핑, `record_id` 기반 upsert 로직, LIVE/SYNTHETIC 분리 집계, `weathercode` 한국어 매핑 구현.

2. **학생이 직접 판단한 일**: Open-Meteo 대전 좌표 선택, 실패 시 마지막 정상값 유지 정책, 어제 대비를 magnitude(절대값)로 표시, 라이브 기록만 이틀 비교에 사용, 채점 AI가 소스로 확인하므로 화면은 최소 정보만 남기고 제출용 텍스트는 README로 이동, 장애 재생 버튼은 카드 3·4 증거를 위해 작게라도 유지, 기온만 보이던 화면에 날씨도 함께 보여주자고 직접 제안해 `weathercode`를 한국어로 매핑하고 행 레벨 `weather_display`로 저장.

3. **AI 제안을 따르지 않은 일**: AI가 어제 대비를 부호 있는 값(+15/−15)으로 표시하자고 했으나 참조 구현(`adapter-reset.example.js`)의 `comparisonFor()`가 `magnitude`(절대값)를 쓰는 것을 확인하고 절대값으로 바꿨습니다. 또한 AI가 날씨를 저장 객체에 넣자고 했으나 스키마의 `additionalProperties: false` 때문에 9개 필드 위반이 되어, 행 레벨 `weather_display`로 분리했습니다. 장애 재생 버튼을 화면에서 완전히 제거하자는 제안도 거부하고, 카드 3·4 재생 증거를 위해 작은 '테스트' 접힘으로 남겼습니다.



## 알려진 제약



- 저장은 브라우저 `localStorage`를 사용합니다. 브라우저 데이터를 지우면 기록도 사라집니다.

- 라이브 조회는 페이지 접속 시 자동 1회 실행됩니다. 하루에 여러 번 접속해도 같은 날짜는 1행으로 갱신됩니다.

- Open-Meteo 응답이 지연되거나 형식이 바뀌면 `timeout`/`schema_error`로 표시되고 마지막 정상값이 유지됩니다.

- 기존에 저장된 기록에는 `weather_display`가 없을 수 있습니다. 이 경우 날씨가 `—`로 표시되며, 같은 날짜를 다시 조회하면 채워집니다.
