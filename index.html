확인 방법 4줄 (T04-C27)

① 어디로 가나요: 이 페이지 상단 "대전 실시간 기온" 히어로와 "관측 정보" 표.
② 3단계 이내 무엇을 하나요: 상단 값·관측/조회 시각 확인 → 심사용 섹션의 장애 재생 5종 버튼 각각 클릭 → 복구 버튼 클릭.
③ 무엇이 보이면 통과인가요: 정상 시 9개 필드가 모두 표시되고, 장애 시 마지막 정상값이 유지되며 상태 배지가 stale·오류 코드로 바뀜. 복구 시 fresh/none으로 돌아오고 전체 행 수가 1→2로 증가하며 어제 대비 delta=15가 표시됨(합성 재생 기준). 라이브 이틀 기록이 2건이면 상단 "어제와 비교"에 실제 변화가 표시됨.
④ 안 될 때 무엇이 보이나요: 네트워크 차단 시 상태 배지가 stale·offline으로 바뀌고 마지막 정상값의 조회 시각이 함께 표시됨.

AI와 나의 판단 3줄 (T04-C28)

① AI에게 맡긴 일: 정보판 HTML/CSS/JS 초안, 9개 필드 정규화 검증, 실패 5종 상태 매핑, record_id 기반 upsert 로직, LIVE/SYNTHETIC 분리 집계 구현.
② 학생이 직접 판단한 일: Open-Meteo 소재 선택, 실패 시 마지막 정상값 유지 정책, delta를 magnitude(절대값)로 표시하기로 결정, stale 라벨 표시 방식, 라이브 기록만 이틀 비교에 쓰기로 결정.
③ AI 제안을 따르지 않은 일: AI가 어제 대비 변화를 부호 있는 값(+15/−15)으로 표시하는 방식을 제안했으나, 참조 구현(adapter-reset.example.js)의 comparisonFor()가 magnitude(절대값)를 쓰는 것을 확인하고 절대값 표시로 바꿨습니다.
